# 学习笔记

## Embedding

**核心作用：** 把文本变成数字向量，让计算机能计算"两段文字有多相似"。embedding 质量直接影响检索召回效果——好的 embedding 能把语义相近的句子放在向量空间的近处，差的就找不到相关内容。

**不同 embedding 的主要差异：**

| 维度 | 说明 |
|------|------|
| 向量维度 | 维度越高信息越丰富，但存储和计算也更贵。`embedding-3` 是 2048 维，OpenAI `text-embedding-3-small` 是 1536 维 |
| 语言能力 | 中文语料用中文优化的 embedding 效果更好；Zhipu 对中文优化更多，OpenAI 中文能力也不差但不是重点 |
| 语义理解深度 | 顶级模型（如 `text-embedding-3-large`）在复杂语义匹配上更准 |
| 最大 token 长度 | 决定一个 chunk 最多能有多长 |

**本项目的选择：** 语料是英文学术论文，Zhipu `embedding-3` 因免费且调用方便作为起点。等第二阶段接入 Ragas 评估后，可以换其他 embedding 对比指标，用数据验证差异。

## 向量索引存储方式

`VectorStoreIndex.from_documents` 内部按顺序做三件事：分块 → 向量化 → 建索引。

**存储方式对比：**

| 方式 | 特点 | 适合场景 |
|------|------|---------|
| 内存（默认） | 无额外依赖，重启丢失 | 临时实验 |
| 本地磁盘持久化 | 写成 JSON 文件，下次直接加载 | 小语料，省 API 调用 |
| ChromaDB | 真正的向量数据库，支持元数据过滤、增量添加 | 中小项目，需要过滤功能 |
| Faiss | 百万级向量，速度极快，纯本地 | 大语料，Windows 安装易出问题 |
| Pinecone / Qdrant | 云端托管，生产级别 | 生产环境 |

**本项目当前方案：** 内存索引 + `persist()` 写到 `index/` 目录，第一次构建后不再重复调 embedding API。

**ChromaDB vs 当前方案的核心区别：** ChromaDB 支持元数据过滤（如只搜索某篇论文），当前方案更轻量但功能少。

**换存储的时机：** 等第四阶段，用 Ragas 指标验证换存储前后有无变化，再决定是否迁移。
